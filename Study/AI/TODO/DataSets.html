這四個資料集在大型語言模型（LLM）的評估領域中扮演著不同的角色，主要可分為程式碼生成和問答與推理兩大類。

以下是它們的使用目的與情境比較：

 

資料集目的與情境比較

 

資料集名稱 核心使用目的 評估能力 (功能) 典型使用情境 所屬領域
HumanEval 評估模型生成 Python 程式碼的能力 (Functionality)。是 Code LLM 領域中最基本且廣泛使用的基準。 函數級程式碼生成、自然語言到程式碼的轉換、解決小型算法問題、函數正確性。 比較不同 LLM 在「編寫獨立、可執行函數」方面的基礎表現。常作為程式碼生成模型的入門門檻。 程式碼生成 (Code LLM)
MBPP (Mostly Basic Programming Problems) 評估模型解決初級程式設計問題的能力，重點在日常實用功能和標準庫應用。 初級程式設計邏輯、字串/列表/數字操作、實用工具函數的生成與單元測試。 評估模型是否能成為初級工程師的助手，解決常見且基礎的 Python 編程任務。與 HumanEval 互補，更強調實用性。 程式碼生成 (Code LLM)
Table Understanding 評估模型理解和處理表格數據的能力，通常涉及從表格中提取結構和語義。 表格結構識別、表格數據提取、表格的語義解釋、將非結構化表格轉換為結構化知識。 從 PDF 報表、網頁或文件中的表格自動提取數據，用於商業分析、金融報告處理或建立知識圖譜。 結構化數據理解 (Structured Data)
TTQA (Tabular and Textual Question Answering) 評估模型在混合內容（表格 + 文本）上的多跳推理和問答能力。 跨模態（表格與文本）推理、多步邏輯推理、結合上下文生成準確答案。 金融報告、研究論文或法律文件問答，其中答案需要整合閱讀文本段落和表格中的數字、事實。 複雜問答與推理 (QA & Reasoning)

重點區分與總結

 

 

1. 程式碼生成 (Code LLM)

 

資料集 關鍵差異
HumanEval 偏向算法挑戰，問題簡潔，類似軟體工程師的面試題。用於測試模型將自然語言翻譯成可工作代碼的核心能力。
MBPP 偏向實用功能，問題較為基礎，強調初級程式設計的常用操作（如字串處理、列表操作）。用於測試模型在日常編程任務中的實用性。

2. 問答與推理 (QA & Reasoning)

 

資料集 關鍵差異
Table Understanding 專注於「理解表格本身的結構和內容」，目標是將表格數據轉換為機器可讀的格式，不一定涉及複雜問答。
TTQA 專注於「從表格和文本中找出答案」，目標是回答複雜問題。它要求模型不僅要理解表格，還要結合表格內容與周圍的文本進行多步、跨文件的邏輯推理。

簡單來說，如果你想知道一個 AI 會不會寫程式，就用 HumanEval/MBPP；如果你想知道一個 AI 會不會讀懂表格，就用 Table Understanding；如果你想知道一個 AI 能不能整合報表和文字資訊來回答複雜的商業問題，就用 TTQA。
