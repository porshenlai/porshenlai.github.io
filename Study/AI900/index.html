異常偵測器

  • 異常偵測器可以監視和偵測時間序列資料中的異常狀況。
  • 例如:識別詐欺性的信用卡支付
  • 例如:透過查找與通常模式的偏差來識別可疑登錄
  • 例如:在監視工業製程感應器結合AI來偵測發生潛在問題的狀況

Azure AI 內容安全

  • 可以由文字，影像和影片中，偵測出潛在具有冒犯意思，惡意，風險或不當的資料內容。
  • 例如:為學生與授課者篩選掉不當的教育內容
  • 例如:為社群軟體對使用者新增的影像，文字和影片進行內容仲裁
  • 例如:為遊戲公司對使用者產生的遊戲成品和聊天室進行內容仲裁

Azure 視覺 API (Vision APIs)

    光學文字辨識 Optical Character Recognition

  • 可以從相片和文件(發票，名片，信件等)中擷取其中印刷和手寫的文字。
  • 例如:識別手寫字母。

    影像分析 Image Analysis

  • 從影像中擷取視覺特徵(物件，臉部，特定品牌，成人內容等)
  • 自動產生標記 (Tag) 描述。
  • 例如:刪除含成人內容的圖片
  • 例如:偵測圖片中狗的影像並取得其座標

    空間分析 Spatial Analysis

  • 從影片中偵測人員的存在和移動，並產生事件供其他程式做事當回應。
  • 其功能包括計算進入指定空間的人數，偵測人員是否戴口罩，以及人員之間的距離。
  • 例如:當空間中超過指定的人數時就產生警示
  • 例如:偵測空間中人員是否遵循社交距離

    自訂視覺 Custom Vision

  • 自行建置，部署和改善專屬的影像識別工具模型。
  • 自訂視覺可以自行指定標籤，提交加上標籤的影像群組，訓練定型，測試，重新定型等步驟來訓練自訂模型。
  • 例如:使用自己的影像來訓練物件偵測
  • 例如:使用自訂模型由零售商店的影像中辨識出競爭對手的產品

    臉部辨識 Face Recognition

  • 提供進階的臉部辨識演算法，來偵測和辨識影像中人類臉部的屬性。
  • 其臉部偵測功能可以感知臉部特徵和屬性(眼鏡，化妝等)。
  • 臉部驗證功能可以根據信賴分數來判斷兩張人臉是否為同一個人。
  • 例如:在社群媒體中的自動標記朋友的圖像

Azure 語音 API (Speech APIs)

    語音轉換文字 Speech to Text

  • 將音訊串流或本機檔案即時轉譯為文字。
  • 例如:製作通話或會議記錄

    • 文字轉換語音 Text to Speech

  • 使用語音合成標記語言(SSML)將輸入的文字轉換成人工合成語音。
  • 例如:要錄製或直播視頻提供隱藏式字幕

    • 語音翻譯 Speech Recognition

  • 將語音即時翻譯成多種語言。
  • 例如:在國際會議中將各國發言人的內容即時翻譯成英語

    • 語音助理

  • 可以開發類似人類自然對話的使用者介面。
  • 例如:使用語音命令打開收音機
  • 例如:語音式的客戶服務專線

    • 語者辨識 Speaker Recognition

  • 根據演算法由個人獨特的語音特性，來驗證和識別出說話者的身分。
  • 例如:根據語音可以辨識出人員是否在參加會議名單中？

Azure 語言 API (Language APIs)

    情感分析

  • 可以分析出文章是屬於正面，中性或負面情感。
  • 例如:確定評論是屬於正面還是負面
  • 例如:根據支援票證中包含的文本了解客戶的不安程度
  • 例如:按照正負尺度評估本文
  • 例如:預測社交媒體貼文的情感
  • 例如:分析客戶評論，並確定每個評論的正面或負面影響

    關鍵片語擷取

  • 可以從文章中以擷取關鍵片語方式，快速識別出文章的主要概念。
  • 例如:確定那些文檔提供了有關相同主題的資訊
  • 例如:確定文件集合中的主要討論點
  • 例如:總結支援票證中的重要資訊
  • 例如:確定某些文件中的主要話題為何？

    具名實體辨識 Named Entity Recognition (NER)

  • 可以識別並分類非結構化文字中的實體。
  • 例如:從支援票證中提取關鍵日期
  • 例如:從文本中提取人員，地點和組織等資訊。

    交談語言理解 Conversational Language Understanding (CLU)

  • 可以將自訂機器學習智慧套用到交談式或自然語言文字，用來預測整體意義並從中提取相關資訊。
  • 例如:以自動聊天方式回答有關退款和兌換問題
  • 例如:輸入問題並互動式回答作為應用程式的一部分
  • 例如:家用智慧設備可以回答諸如 “今天天氣會如何？” 之類的問題
  • 例如:使用知識庫以交互方式回答使用者問題的網站
  • 例如:讓使用者能夠自行在網站上尋找答案的聊天機器人
  • 例如:透過在公用網站中爬文來建立 FAQ 的服務
  • 例如:餐廳可以使用聊天機器人提供預訂服務與回答問題

    問題解答

  • 使用者用自然語言提出問題，再由 AI 系統給予適當的答案。
  • 問題解答可讓你定義可使用自然語言輸入查詢的問答組知識庫。
  • 多回合交談可在呈現明確答案前，從使用者引出更多資訊。
  • 例如:使用自然語言來查詢知識庫
  • 例如:讓知識庫為提供相同的答案給相似提問
  • 例如:已有FAQ PDF檔，根據FAQ建立對話支援
  • 例如:基於 FAQ 創建機器人

負責任的 AI

    公平性

  • AI 應用程式應該公平的對待所有人，不得因為性別，年齡，種族，宗教或其他因素而影像預測結果。
  • 訓練 AI 系統資料集的偏差，不應該反映於 AI 系統的結果就是遵守公平性原則。
  • 例如:建立機器學習模型來支援銀行申請貸款的核准時，不得有任何性別，種族，宗教或其他因素的偏見，導致特定族群的客戶獲得不公平的優勢或劣勢。
  • 例如:按不同銷售目標區域有不同定價。

    可靠性與安全性

  • 開發 AI 應用程式時，必須嚴格遵守測試和部署的管理程序，確保能如預期運作才能發行。
  • 發行後仍然必須持續監視和追蹤模型，必要時須重新訓練建立新模型，來確保系統的可靠性與安全性。
  • 為自動駕駛汽車開發 AI 系統時，要確保系統在其使用壽命內能持續運行
  • 機器學習模型用於診斷病患症狀並建議處方

    透明度

  • AI 應用程式應該是公開透明，預測的結果是可以被了解和解釋。
  • 無論是專家或使用者，都要能夠明確了解AI系統的用途和運作方式，以及預測的限制。
  • 例如:處理提供給 AI 系統的異常值或缺失值
  • 例如:自動決策程序必須加以記錄，已便已核准使用者可以了解決策制定原因
  • 例如:評估是否應該核准貸款的 AI 系統時，制定決策所用的因素要可以解釋

    包容性

  • AI 裝置應改造福社會中的每個人，AI 設計應考慮所有人類的各種情況。開發系統時不只遵守技術規範，還要兼顧倫理與同理心的需求。
  • 例如:給予所有人許可權的AI系統，包括有聽覺，視覺和其他障礙的人
  • 例如:預測性應用程式會為視覺不便的使用者提供音訊輸出
  • 例如:探索語音辨識技術在智慧型家用裝置中的使用，可找出無意間遺漏特定使用者群組的任何頻障

    隱私權與安全性

  • 必須保護及保障個人與企業資訊。
  • 例如:為消費者提供有關其數據的收集，使用和儲存的資訊和控制。
  • 例如:只有已核准的特定使用者可以看見個人資料。

    權責性

  • 以 AI 為基礎的解決方案，設計和開發人員應該在有明確準則的組織架構中工作。
  • 確保方案符合道德和法律標準。
  • 設計和部屬 AI 系統的人員，必須為 AI 的動作和預測負責，尤其是當不斷發展更多系統時，更需注重權責。
  • 例如:實施過程以確保 AI 系統所做的決定可以被人類推翻。

模型的種類

監督式學習

  • 將附上 標籤 (label) 的資料，交給機器學習模型定型來找出最佳解答
  • 資料集的欄位稱為 特徵 (feature)
  • 指定為標籤的欄位稱為 標籤 或 目標
  • 為資料指定標籤的動作稱為 標記 或 預定義
  • 分成 分類 和 迴歸 兩大類
  • 例如: 輸入500張附有貓和老虎標籤的圖片，作為模型的定型資料訓練後，再輸入新的沒有標籤的圖片，驗證模型是否能正確辨識出是貓還是老虎。 [1]

非監督式學習

  • 沒有標記標籤，模型自己探索資料間的規律，找出資料特徵，達成解答未知資料的目標。
  • 叢集分析式式非監督式學習最常見的方法，會根據特徵由演算法計算資料間的相似度，將資料區分為不同群組。 [1]

半監督式學習

  • 介於監督式與非監督式間的機器學習
  • 透過少量有標籤的資料找出特徵，就能對其它大量無標籤的資料進行預測 [1]
  • 可以減少標記資料的時間和人力，又能預測出準確的結果

增強學習

  • 電腦經由和動態環境不停互動來學習正確完成任務的過程 [1]
  • 嘗試錯誤 (trial and error)
  • 根據外界的回饋資料隨時修正行動，反覆嘗試錯誤來獲得最大報酬

分類模型: 決策樹 (Decision Tree)

  • 監督式學習，標籤值為「是」或「否」
  • 可適用於分類或迴歸模型
  • 算法接近人類的思考邏輯，容易理解運算原理與預測結果
  • 速度快，適合處理大數據
  • 深度過深時容易擬合過度

分類模型: 羅吉斯回歸

  • 監督式學習，運用於分類模型 [1]
  • 找出一條能夠將所有資料清楚地分開的直線
  • 預測範圍 0 ~ 1 代表目標值為 「是」或「否」的機率
  • 不是合解決非線性問題

分類模型: 支援向量機 (SVM)

  • 監督式學習
  • 可以畫出最能分隔資料的邊界，適用於分類，迴歸和偵測離群值 [1]
  • 適合多高維度，訓練資料少的資料集。

分類模型: K 近鄰 (K-NN)

  • 監督式學習，分類模型
  • 將資料轉為向量，再用資料間的距離來換算成資料的近似度
  • 根據近似度作為分類的標準
  • 選取近似度最高的Ｋ筆資料所屬最多的分類 [1]
  • 各分類樣本數量差異多時易錯誤

分類模型: 貝氏分類器 (Naive Bayes Classifier)

  • 根據事件的發生次數，來計算事件發生的機率。
  • 貝氏分類為貝氏定理 (Bayes’ theorem) 的應用。模型中假設所有的特徵都是獨立不會相互影響，所以使得計算大大簡化。
  • 經過計算可以得知某筆資料對各標籤目標的發生機率，機率最高的標籤就是所屬的分類。
  • 資料量夠多時，簡單又有效，不易過度擬合。特徵數多時，易有運算誤差。

機器學習的工作流程

問題定義

  • 了解問題
  • 將方案的抽象目標轉化成可以量化的具體項目
  • 例如:將「降低工廠營業成本」轉化成「預測下個月的最適當生產量」。

資料蒐集

  • 收集資料的集合稱為資料集 (dataset)
  • 將多個資料集合併成單一的資料集
  • 確保資料集中的資料值具有相似規模，避免超出正常範圍的離群值
  • 例如: 開發預測美國汽車駕駛人保險金額的機器學習模型時，想降低系統的偏差就要取得代表美國人口的定型樣本資料集，而不是日本或全球的樣本。

資料準備

  • 資料清理 (data clearing)
    • 資料正規化 (normalization)
    • 資料標準化 (standardization)
    • 移除異常資料 (遺漏值，無效值，離群值)
  • 特徵工程 (feature engineering)
    • 將原始資料處理成為「特徵」
    • 學習模型以特徵為輸入的資料，以標籤為輸出的預測
    • 特徵是觀察對象中獨立且可測量的屬性，代表模型所處理的實際項目。
    • 特徵抽取 (feature extraction)
      • 從資料集中發掘可用的特徵。
      • 轉化出量化的多維度資料。
    • 特徵選擇 (feature selection)
      • 根據機器學習模型的目標，分析挑選重要的特徵。
      • 例如: 購物網站若要預測推薦的商品，應該使用「產品名稱」作為特徵，因為產品名稱和消費習慣相關。
  • 資料分割 (data split)
    • 70~80% 訓練(定型)資料，20~30% 測試(評估)資料

模型選擇

  • 機器學習的目標是找出解決問題的最佳方案
  • 依照問題的性質，資料量，資料類型，運算效能等情況全面衡量，來選擇最合適的模型。
  • 模型種類有: 1) 分類，2) 迴歸，3) 叢集等。

模型定型與模型評估

  • 使用分割出來的訓練(定型)資料集，對機器學習模型進行訓練(定型)。
  • 使用分割除來的測試(評估)資料集，來測試模型的準確性與執行效能。
  • 預測結果的準確性很低時，就必須重新定型模型。

參數調整

  • 調整模型演算法中的 超參數 (hyperparameter)，讓模型預測結果更真實。
  • 定義模型的相關屬性或定型過程的參數就稱為 超參數
  • 參數過度調整可能會造成 凝合過度 (overfitting)

臉部識別原理

  • 生物辨識技術有指紋辨識，虹膜辨識，聲音辨識，人臉辨識... 等
  • 人臉辨識利用人臉五官輪廓的距離角度來建立3D結構模型，以向量方式擷取臉部特徵點偵測值，進行身分辨識
  • 優點包括：非接觸式，攝像裝置普及，辨識速度快，不易已照片作假，不受裝扮物件影像，直接取像，不需使用者配合。
  • 臉部識別功能：身分識別, 存取授權, 顧客分析, 健康管理

使用交談語言理解建立語言模型

  • 電腦不僅能接受輸入的語言，也能夠解讀輸入語言的語義。
  • Azure 透過語言服務所提供的「交談語言理解」(CLU) 來處理
  • CLU 為「對話語言理解 (LUIS: Language Understanding) 的進階版。
能夠由對話中得到下列三核心概念
  • 表達方式 : 使用者所要表述的內容 (Ex: 好熱喔! 打開冷氣。)
  • 實體 (Entity)：言語中所指稱的特定項目 (Ex: 冷氣)
  • 意圖 (Intent)：期待得到的某項結果 (Ex: 啟動設備)
無法辨識意圖時，預設為 None (無意圖) 會被視為後備的處理程序。

大語言模型

LLM 是一種特殊類型的機器學習模型，用來執行自然語言處理工作，包含情感判斷，分類，文字摘要，比較多個文字來源的語意相似性，產生新的自然語言...等。

基礎架構 - 轉換器模型(Transformer models)

  • 搭配 token 化，內嵌計算等技術，經深度學習完成生成自然語言的任務。
  • 預先用大量的文字進行訓練，讓模型能夠解析單字之間的語意關聯性，並使用這些關聯性來判斷文字序列的意義。
  • 包含 1) 編碼器(Encoder) 與 2) 解碼器(Decoder) 兩個區塊。
    1. 編碼器負責建立 token 語意的向量編碼
    2. 解碼器負責生成新的文字序列

Token 化 (Tokenization)

內嵌計算 (Embeddings)

  • 為每個 token 定義一個向量 (vector) 來表示 token 的語意關聯性，這個技術稱為內嵌計算
  • 語意相關的 token 在空間中的距離回更相近

下一個 token 預測 (Next Token)

  • 轉換器模型中的編碼器和解碼器區塊包含多層，組成模型的類神經網路
  • 注意層 (attention layer) 用來檢查 token 向量序列的技術，並量化各 token 之間的關聯性強度。
  • 自我注意力 (self-attention) 機制會考慮到整個文本序列中的所有 token，並計算之間的交互影響，如此能夠理解各 token 在上下文本中的具體含意，從而深入理解整個文本的語意。
  • 注意層會仔細檢查句子中的每個 token，並判斷出其內嵌向量值。
  • 向量值是用該 token，以及和其經常搭配的 token 間的關聯性為基礎，同一個字可能會有多個內嵌向量值，視使用的內容而定。
  • 解碼器區塊中，注意層是用來預測輸出文字序列中的下一個 token，模型會考量採用哪個 token 會最具影響力。

轉換器模型架構中的三個階段為何？ (多選題，通常指關鍵處理步驟)

Transformer 模型的核心步驟通常涵蓋：
  • Token 化 (Tokenization)：將輸入文字切分成較小的單元 (Tokens)。
  • 內嵌計算 (Embedding Calculation)：將 Tokens 轉換成數值向量 (Embeddings)。
  • 注意力機制 (Attention)：處理 Tokens 之間的關係。
  • 輸出生成 (例如：下一個 Token 預測)。
雖然「下一個 Token 預測」是 LLM 的工作/目標，但 Token 化 和 內嵌計算 是處理輸入數據的基礎步驟。通常在討論 LLM 的工作流程時，這三個 (Tokenization, Embedding, 下一個 Token 預測/Attention) 都是非常關鍵的環節。
