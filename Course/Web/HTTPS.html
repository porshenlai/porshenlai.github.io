SSL 請求的步驟

讓我們詳細說明瀏覽器在使用 HTTPS 時，TCP 連線建立、SSL/TLS 憑證驗證以及 SSL/TLS 握手 (Handshake) 的完整程序。

當你在瀏覽器中輸入一個 https:// 開頭的網址時，會發生以下步驟：

步驟 1：DNS 解析 (DNS Resolution)

  • 瀏覽器首先會透過 DNS (Domain Name System) 將網域名稱（例如：www.example.com）解析成對應的 IP 位址。

步驟 2：TCP 連線建立 (TCP Connection Establishment)

  • 一旦瀏覽器取得伺服器的 IP 位址，它就會嘗試與伺服器建立一個 TCP 連線。
  • 這是透過 TCP 的 三次握手 (Three-way Handshake) 機制完成的：
    1. SYN (Synchronize)：瀏覽器發送一個 SYN 封包到伺服器（通常是 443 埠）。
    2. SYN-ACK (Synchronize-Acknowledge)：伺服器收到 SYN 後，發送一個 SYN-ACK 封包作為回應，確認收到並準備好建立連線。
    3. ACK (Acknowledge)：瀏覽器收到 SYN-ACK 後，發送一個 ACK 封包作為最終確認。
  • 此時，一個可靠的 TCP 連線就已經建立了，但這只是底層的網路連線，還沒有進行加密。

步驟 3：TLS 握手 (TLS Handshake) - 加密連線的建立與憑證驗證

TLS 握手是 HTTPS 最核心的部分，它負責建立加密參數、交換金鑰，並驗證伺服器身份。

  1. Client Hello (客戶端問候)
    • 瀏覽器發送 Client Hello 訊息給伺服器。此訊息包含：
      • 支援的 TLS 版本 (e.g., TLS 1.2, TLS 1.3)。
      • 客戶端生成的隨機數 (Client Random)，用於後續生成對稱金鑰。
      • 支援的加密套件列表 (Cipher Suites)，包含加密演算法、金鑰交換演算法、雜湊演算法等。
      • 支援的壓縮方法。
      • SNI (Server Name Indication)：指示客戶端要連線的網域名稱，以便伺服器在多個網站共用一個 IP 位址時，能提供正確的憑證。
  2. Server Hello (伺服器問候)
    • 伺服器收到 Client Hello 後，回應 Server Hello 訊息。此訊息包含：
      • 選擇的 TLS 版本 (從客戶端提供的列表中選擇伺服器支援的最高版本)。
      • 伺服器生成的隨機數 (Server Random)，用於後續生成對稱金鑰。
      • 選擇的加密套件 (從客戶端提供的列表中選擇一個雙方都支援的)。
      • 選擇的壓縮方法。
  3. 伺服器憑證、Server Key Exchange (伺服器金鑰交換，若需要)、Server Hello Done (伺服器問候完成)
    • 伺服器發送其數位憑證 (Server Certificate) 給瀏覽器。這個憑證包含：
      • 伺服器的公開金鑰。
      • 憑證簽發者 (CA) 的資訊。
      • 憑證的有效期、網域名稱等。
      • 憑證鏈 (Certificate Chain)：包含伺服器憑證本身以及所有中繼憑證，直到根憑證。
    • 憑證驗證 (Certificate Verification)：
      • 瀏覽器收到伺服器憑證後，會進行一系列嚴格的驗證：
        • 憑證是否有效？ (是否過期？是否在有效期內？)
        • 憑證是否被撤銷？ (查詢 CRL 或 OCSP 列表)。
        • 憑證上的網域名稱是否與請求的網域名稱匹配？ (例如，訪問 www.example.com 時，憑證必須是為 www.example.com 或其萬用字元發行的)。
        • 憑證是否由受信任的 CA 簽發？ 瀏覽器內建一個信任根憑證儲存區 (Trust Store)，包含所有受信任 CA 的公開金鑰。瀏覽器會沿著憑證鏈往上追溯，直到找到一個受信任的根憑證。如果鏈條無效或 CA 不受信任，瀏覽器會發出警告。
    • Server Key Exchange (可選)：如果選擇的加密套件使用 Diffie-Hellman 或 Elliptic Curve Diffie-Hellman (ECDHE) 等演算法進行金鑰交換，伺服器會在此步驟發送其金鑰交換的公開參數。這是實現前向保密 (Forward Secrecy) 的關鍵，因為即使私密金鑰被洩露，過去的通訊也無法被解密。
    • 伺服器發送 Server Hello Done，表示伺服器已經將所有必要的初始訊息發送完畢。
  4. Client Key Exchange (客戶端金鑰交換)、Change Cipher Spec (改變加密規範)、Encrypted Handshake Message (加密的握手訊息)
    • Client Key Exchange：瀏覽器收到並驗證憑證後，根據之前 Client Random、Server Random 和伺服器的公開金鑰（或金鑰交換參數），計算出一個預備主金鑰 (Pre-Master Secret)。然後，它會：
      • 使用伺服器的公開金鑰加密這個 Pre-Master Secret。
      • 將加密後的 Pre-Master Secret 發送給伺服器。
      • (注意：在 TLS 1.3 中，金鑰交換的流程有所簡化，主要是在 Client Hello 和 Server Hello 階段就完成，減少了往返次數，並強化了前向保密性。上述描述主要針對 TLS 1.2 或更早版本。)
    • 瀏覽器和伺服器各自生成主金鑰 (Master Secret)： 雙方都使用 Client Random、Server Random 和 Pre-Master Secret，通過一個金鑰導出函式，導出主金鑰 (Master Secret)。
    • 生成會話金鑰 (Session Keys)： 雙方再從 Master Secret 導出用於實際資料加密的對稱會話金鑰 (Symmetric Session Keys)，包括加密金鑰 (Encryption Key) 和訊息認證碼金鑰 (MAC Key)。
    • Change Cipher Spec (客戶端)：瀏覽器發送 Change Cipher Spec 訊息，告知伺服器從現在開始，後續的所有通訊都將使用新協商出的對稱會話金鑰進行加密。
    • Encrypted Handshake Message (客戶端)：瀏覽器發送一個加密的 Finished 訊息，包含所有握手訊息的雜湊值，用於驗證整個握手過程沒有被篡改。這是第一個使用新會話金鑰加密的訊息。
  5. Change Cipher Spec (伺服器)、Encrypted Handshake Message (伺服器)
    • 伺服器收到瀏覽器的 Change Cipher Spec 和加密的 Finished 訊息後：
      • 它會嘗試使用自己計算出的會話金鑰解密 Finished 訊息。
      • 如果解密成功且雜湊值匹配，則表示雙方成功地達成了金鑰交換和加密參數的協商。
      • 伺服器也發送自己的 Change Cipher Spec 訊息。
      • 伺服器發送一個加密的 Finished 訊息。

步驟 4：安全連線建立 (Secure Connection Established)

  • 至此，TLS 握手完成。
  • 現在，瀏覽器和伺服器之間建立了一個雙方信任且加密的通道。
  • 所有後續的 HTTP 請求和回應都將使用在 TLS 握手階段協商出的對稱會話金鑰進行加密和解密。

總結圖解

為了幫助理解，您可以想像一個流程圖：

  1. 瀏覽器 (Client) ----(DNS Lookup)----> DNS Server
  2. 瀏覽器 (Client) <----(IP Address)---- DNS Server
  3. 瀏覽器 (Client) ----(SYN)----> Web Server
  4. 瀏覽器 (Client) <----(SYN-ACK)---- Web Server

  5. 瀏覽器 (Client) ----(ACK)----> Web Server

    (TCP 連線建立完成)

  6. 瀏覽器 (Client) ----(Client Hello)----> Web Server

  7. 瀏覽器 (Client) <----(Server Hello, Certificate, [Server Key Exchange], Server Hello Done)---- Web Server

    (此時瀏覽器驗證憑證)

  8. 瀏覽器 (Client) ----(Client Key Exchange, Change Cipher Spec, Encrypted Finished)----> Web Server

  9. 瀏覽器 (Client) <----(Change Cipher Spec, Encrypted Finished)---- Web Server

    (TLS 握手完成，安全連線建立)

  10. 瀏覽器 (Client) <---> (加密的 HTTP 請求/回應) <---> Web Server

HTTPS: 如何安裝

設定 HTTPS 連線的步驟主要可以分為四個階段：憑證準備、伺服器設定、重新導向以及定期維護。

HTTPS (Hypertext Transfer Protocol Secure) 的核心是利用 SSL/TLS 憑證來加密客戶端（瀏覽器）和伺服器之間的通訊。

第一階段：憑證準備 (取得 SSL/TLS 憑證)

這是啟用 HTTPS 最關鍵的第一步。

  1. 產生金鑰對 (Key Pair)：
    • 在您的伺服器上，首先要生成一組公開金鑰 (Public Key) 和私密金鑰 (Private Key)。
    • 私密金鑰必須安全地保存在伺服器上，絕不能洩露。
    • 公開金鑰將會包含在憑證中。
  2. 建立憑證簽署請求 (CSR - Certificate Signing Request)：
    • 使用生成的公開金鑰，建立一個 CSR 文件。
    • CSR 包含您的域名、組織名稱、城市、國家等資訊。
  3. 向憑證授權機構 (CA) 申請/購買憑證：
    • 將 CSR 提交給可信任的 CA (例如：Let's Encrypt, DigiCert, Sectigo 等)。
    • CA 會進行網域驗證 (Domain Validation, DV)，以確認您確實擁有該網域。
    • 驗證成功後，CA 會用其私密金鑰對您的公開金鑰和資訊進行數位簽章，並頒發給您：
      • 伺服器憑證 (Server Certificate)：證明您伺服器身份的文件。
      • 中繼憑證 (Intermediate Certificates)：用於建立從您的憑證到 CA 根憑證的信任鏈 (Certificate Chain)。

第二階段：伺服器設定 (安裝憑證)

將取得的憑證安裝到您的網頁伺服器軟體（如 Apache, Nginx, IIS 等）。

  1. 安裝私密金鑰和伺服器憑證：
    • 將在第一階段生成的私密金鑰和從 CA 取得的伺服器憑證檔案上傳到伺服器上的安全位置。
  2. 配置憑證鏈 (Certificate Chain)：
    • 將伺服器憑證、所有中繼憑證組合成一個完整的憑證鏈檔案。這對於瀏覽器能成功驗證您的憑證非常重要。
  3. 配置伺服器監聽 HTTPS 埠：
    • 修改您的伺服器設定檔，啟用 443 埠（HTTPS 的標準埠）。
    • 在 443 埠的設定中，指定您剛才安裝的私密金鑰和憑證鏈檔案的路徑。
  4. 選擇安全的加密協定和套件：
    • 在伺服器設定中，確保只啟用最新的 TLS 1.2/1.3 協定，並禁用不安全的舊版 SSL/TLS 協定。
    • 選擇強健的加密套件 (Cipher Suites)，例如使用 ECDHE 進行金鑰交換，並使用 AES-256 GCM 進行對稱加密。
  5. 重新啟動伺服器：
    • 重新載入或重新啟動網頁伺服器，讓新配置生效。

第三階段：強制轉導和安全性強化

確保所有使用者都透過安全的 HTTPS 連線存取網站。

  1. 設定 HTTP 轉導至 HTTPS (Redirection)：
    • 配置伺服器，將所有來自 HTTP (埠 80) 的請求，使用 301 永久轉址，自動導向到對應的 HTTPS (埠 443) 網址。
  2. 處理混合內容 (Mixed Content)：
    • 檢查您的網頁程式碼和內容，確保所有資源（圖片、腳本、樣式表等）的 URL 都使用 https:// 開頭，而不是 http://。若網頁中同時包含 HTTPS 和 HTTP 資源，瀏覽器會發出「混合內容」警告，這會降低安全性。
  3. 啟用 HSTS (HTTP Strict Transport Security)：
    • 在 HTTPS 的回應標頭中加入 Strict-Transport-Security 標頭。
    • HSTS 會指示瀏覽器，在一段時間內（例如一年），即使使用者輸入 http://，也強制使用 HTTPS 連線，從根本上防止降級攻擊 (SSL Stripping)。

第四階段：定期維護和測試

  1. 測試憑證和連線：
    • 使用 SSL 測試工具（例如 Qualys SSL Labs 的 SSL Server Test）來檢查您的伺服器配置是否安全、憑證鏈是否完整，以及評分是否達到 A 或 A+。
  2. 憑證更新：
    • SSL/TLS 憑證都有有效期（通常為 90 天到一年）。
    • 您必須在憑證過期前重新申請並安裝新的憑證。許多免費 CA (如 Let's Encrypt) 都提供自動續期工具，強烈建議設定。
