零資料保留（Zero Data Retention, ZDR）模式

  • 是一種極端的資料隱私策略，旨在從架構層面保護使用者個資，其核心原則是資料用完即刪。
  • 主要是透過消除潛在的風險點，而不是僅依賴政策或合約。
  • 零資料保留模式如何保護個資：
    • 消除儲存風險（The Ultimate Protection）
      • 即時刪除： ZDR 模式確保服務器在處理完畢您的輸入（例如，您對 AI 提出的問題、輸入的程式碼、上傳的語音）並返回結果的瞬間，就將您的資料從臨時記憶體中清除。
      • 無紀錄、無痕跡： 系統不會將您的輸入、輸出或相關的識別資訊（如 Session ID、Email）寫入到永久儲存（Persistent Storage）設備，包括資料庫、硬碟日誌檔（Logs）或備份系統。
      • 優勢：
        • 無物可竊： 如果資料從未被儲存，駭客在資料洩露事件中就無法竊取這些資料。這是最直接、最物理性的安全保障。
        • 無物可供調閱： 在法律調查或政府機關要求調閱資料時，因為系統沒有儲存任何東西，所以無法提供您的輸入內容。
    • 防止內部濫用與重複使用
      • 隔離訓練資料： ZDR 模式確保您的輸入資料絕對不會被用於訓練或改進底層的 AI 模型。這對於企業客戶或處理專有資訊的個人來說至關重要。
      • 消除人工審核： 為了確保隱私，ZDR 環境中的資料通常不會被儲存在可以供人工（例如服務提供者的安全或審核團隊）審查的系統中。服務提供者只能依賴即時的自動化機制來進行濫用監控。
    • 簡化法規遵循（Compliance）
      • 符合嚴格法規： 對於受高度監管的行業（如金融的 PCI-DSS、醫療的 HIPAA、或全球的 GDPR），ZDR 模式極大地簡化了合規性。因為沒有資料保留，企業更容易證明他們符合「資料最小化」和「儲存限制」的原則。
      • 縮小審計範圍： 沒有長期儲存的資料，意味著法規審計時需要檢查的資料足跡和系統會大幅減少，降低了企業的風險與成本。
  • ZDR 的實作方式（通常用於企業級服務）： 雖然原理簡單，但實際實作 ZDR 模式需要複雜的技術架構：
    • 揮發性記憶體（Volatile Memory）： 處理都在臨時記憶體 (RAM) 中完成。一旦請求完成，該處理程序所佔用的記憶體就會被釋放和覆寫。
    • API 端點（Endpoint）： 通常只針對特定的 API 服務或企業級套件提供 ZDR 選項，這需要客戶主動申請並開啟，因為啟用 ZDR 會影響部分功能（例如：您將無法查看歷史紀錄或繼續上次的對話）。
    • 合約擔保： 服務提供者會提供零資料保留合約（ZDR Agreement），在合約中明確承諾輸入和輸出資料不會被儲存。
  • 總結來說，零資料保留模式不是一種技術，而是一種資料架構承諾： 「我們保護您的個資，是因為我們從未持有它。」

零信任架構（Zero Trust Architecture, ZTA）

  • 是一種安全模型，其核心原則是「永不信任，始終驗證（Never Trust, Always Verify）」。
  • 假設任何使用者、裝置、應用程式或網路流量，無論來自內部網路還是外部網路，都必須經過嚴格驗證才能存取資源。
  • 零信任模型並非單一產品，而是一套設計理念和實施原則。ZTA 的七大核心特徵包括：
    1. 以身份和內容為中心（Identity and Context-Centric）
      • 強大的身份驗證（Strong Authentication）： 存取任何資源前，必須使用多重身份驗證（MFA）來驗證所有使用者、裝置和應用程式的身份。
      • 持續驗證（Continuous Verification）： 驗證不是一次性的。即使使用者已登入，系統也會持續監控和重新驗證其身份、存取權限和行為，確保存取權限在整個會話期間都是有效的。
      • 情境感知（Context Awareness）： 存取決策不僅基於身份，還基於多種情境因素，例如：
        • 使用者身份：他是誰？
        • 裝置狀態：裝置是否健康（例如：已安裝防毒軟體、最近已修補）？
        • 存取地點：從哪裡發出請求？
        • 存取時間：是否在正常工作時間？
      • 最小權限原則（Principle of Least Privilege, POLP）
        • 嚴格限制存取範圍： 任何實體（使用者或裝置）只被授予完成其任務所需的最低存取權限。權限是精確授予的，而不是預設開放的。
        • 即時/按需存取（Just-in-Time / Just-Enough Access）： 權限應在需要時才授予，並在任務完成後立即撤銷。這可以最大限度地減少潛在的攻擊面。
      • 微分段與隔離（Micro-segmentation and Isolation）
        • 網路微分段： 傳統上，網路被劃分為大區塊（內部信任、外部不信任）。ZTA 將網路細分成許多小的、獨立的安全區域（微分段）。
        • 隔離與控制： 即使攻擊者成功入侵某個區段，他們也無法輕易地橫向移動（Lateral Movement）到其他區段。所有區段之間的流量都需要經過驗證和授權。
      • 偵測與自動化（Detection and Automation）
        • 持續監控（Continuous Monitoring）： 所有的網路流量、資源存取和使用者行為都會被持續監控、記錄和分析。
        • 分析驅動的決策： 使用行為分析（UEBA）和機器學習來即時偵測異常或惡意的活動。
        • 自動化回應： 一旦偵測到威脅，系統會自動採取快速、可擴展的回應措施，例如隔離受感染的裝置、撤銷存取權限。
      • 統一策略執行（Unified Policy Enforcement）
        • 集中管理： 無論資源在本地、雲端還是在混合環境中，存取策略都是在中央策略引擎中定義和管理的。
        • 一致性： 存取控制策略在整個企業 IT 生態系統中保持一致，防止安全漏洞。
      • 強調資料保護（Focus on Data Protection）
        • 資料為核心資產： ZTA 的最終目標是保護資料本身。所有安全措施都圍繞著資料，無論資料儲存在哪裡或正在傳輸到哪裡。
        • 資料分類與加密： 透過資料分類來區分敏感度，並在資料傳輸和靜止時強制執行加密。
      • 裝置健康度檢查（Device Posture Check）
        • 裝置納入考量： 存取資源的裝置（筆記型電腦、手機、伺服器）被視為與使用者身份一樣重要的安全元素。
        • 完整性檢查： 在授予存取權之前，系統會檢查裝置的安全狀態（例如：作業系統是否最新、是否有未修補的漏洞、是否符合企業安全標準）。
  • 簡而言之，零信任架構的設計原則是不依賴網路邊界，而是將安全控制移動到每一個資源的周圍。
