I. 課程啟動與目標 (15 min)

課程目標與核心概念

  • 學會將 **Prompt (提示詞)** 視為專案的 **「設計資產」**，納入 Git 版本控制。
  • 掌握利用 Git/GitHub 功能 (Log, Diff, Blame, Code Review) 來追蹤 LLM 程式碼的生成與迭代。
  • 建立團隊協作模式：**Prompt-Code-Review-New Prompt** 的敏捷循環。
**傳統開發：** 程式碼是核心。
**AI 輔助開發：** **提示詞 (Prompt)** 是核心，程式碼是產物。

II. 核心方法論：Prompt-Driven Development (20 min)

Prompt 即 Commit Log 的重要性

  • **可追溯性 (Traceability):** 每次 Commit 的程式碼修改，都必須對應到產生它的 Prompt。
  • **協作基礎:** 隊友檢視程式碼時，可以立即從 Log 了解**「最初的設計意圖」**。
  • **未來優化:** 累積的 Prompt 歷史是未來訓練或微調 LLM 的寶貴資料集。

Commit Log 格式建議

欄位內容目的
**標題 (Subject)**`[Prompt]: <核心提示詞>`快速了解本次修改的驅動指令。
**內文 (Body)***可選*，詳細說明本次人工微調/測試結果。提供額外的脈絡與驗證細節。

💡 範例：`[Prompt]: 請寫一個計算斐波那契數列的 Python 函式，並加上型別註記。`

III. 實戰演練：首次生成與團隊協作 (30 min)

步驟一：初版程式碼生成與上傳

  1. **設計 Prompt:** 撰寫第一個清晰、明確的提示詞 (例如：`[Prompt]: 請用 C++ 寫一個計算質數的函式，並包含測試用例。`)。
  2. **LLM 生成:** 將 Prompt 輸入給 LLM，取得程式碼。
  3. **Git 提交:** 將程式碼檔案加入 Git，並使用**完整的 Prompt** 作為 Commit Log 提交。 
    git add <檔案名>
    git commit -m "[Prompt]: 請用 C++ 寫一個計算質數的函式，並包含測試用例。"
  4. **推送到 GitHub:** `git push origin `。

步驟二：團隊 Code Review 與缺陷標記

  • **GitHub Pull Request (PR):** 提交 PR 進行審核。
  • **Code Review:** 隊友閱讀程式碼，並在 PR 介面中留下具體修改建議。
  • **使用 `git blame`：** 在 GitHub 介面上，點擊 `blame` 鍵，每一行程式碼都會指向**第一個 Prompt Commit**，證明其來源。

IV. 程式碼微調與 Prompt 迭代 (45 min)

步驟三：設計新的 Prompt 進行修正

  • **意見收斂:** 根據 Code Review 的建議，設計出一個新的、更精確的 Prompt。
  • **新 Prompt 範例:** 
    [Prompt]: 請修正函式中對偶數的錯誤判斷，並將 C++ 的測試用例改用 Catch2 框架實現。
  • **LLM 修正:** 將**舊程式碼 + 新 Prompt** 傳給 LLM，要求其修正。

步驟四：檢視差異與版本更新

  1. **檢視差異 (Diff):** 在本地使用 `git diff` 仔細比較 LLM 做了哪些修改。
  2. **提交修正:** 使用**新的 Prompt** 作為 Commit Log 提交。 
    git add <檔案名>
    git commit -m "[Prompt]: 請修正函式中對偶數的錯誤判斷，並將 C++ 的測試用例改用 Catch2 框架實現。"
  3. **推送到 GitHub:** 進行第二次 `push`。
**思考：** 如果 LLM 的修正不完整或引入新錯誤，你該怎麼辦？ (答：設計第三版 Prompt)

V. 總結：Log, Diff, Blame 的威力 (10 min)

Git 核心功能如何服務於 LLM 開發

  • **`git log` 追蹤歷史:** 執行 `git log --oneline`，你看到的是**完整的 Prompt 演化歷史**，而非單純的程式碼修改。
  • **`git diff` 驗證修正:** 確保 LLM 的修改範圍和內容是可控且符合預期的，避免「黑箱」修正。
  • **`git blame` 溯源責任:** 任何一行程式碼，都能追溯到是**哪一個 Prompt** 驅動了它的生成，提升問題排除效率。

課程總結與 Q&A

核心 Takeaway

1. Prompt 必須版本化。
2. Commit Log = Prompt 歷史。
3. 協作基於 Log 與 Review。
